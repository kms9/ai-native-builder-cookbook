## 五部分学习路径

1. **角色为什么出现**：理解企业 AI 建设中的责任断层，以及外部 FDE 与内部 AI Native Builder 的合作边界。
2. **看见 AI 系统背后的企业**：从业务结果、能力和决策进入知识、领域模型、Operational Ontology，再确定 Workflow 与 Agent 的位置。
3. **完成一次端到端建设**：从可验证场景走到工作流、智能体约束、运行系统和评估治理。
4. **从试点走向组织能力**：判断真实采用、产品责任、资产复用和退役，并建立从 Trace 与失败回到组织资产的学习闭环。
5. **用作品说明能力**：用主张、证据、运行结果和限制完成毕业项目与同行复核。

这条路径最终要回答一个问题：**AI 怎样进入一个真实组织，理解业务世界，并产生可靠行动？**

本书不会把答案压成“选一个更强模型”。业务目标决定系统为什么存在；知识和业务语义决定 AI 根据什么理解世界；Workflow、Agent 与 Action 决定它怎样行动；Runtime、权限、Trace 和 Eval 决定这些行动能否被控制、解释和恢复；持续复盘再把运行经验沉淀回知识、规则、Skill、Workflow 与 Ontology。
