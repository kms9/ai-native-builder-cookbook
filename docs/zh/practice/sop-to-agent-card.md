## 业务约束版完成检查

- [ ] 触发、输入、开始状态和完成状态能够说明；
- [ ] 现状事实、现行 SOP 和目标流程没有混写；
- [ ] AI 可做与不可做具体到动作、字段或环境；
- [ ] 每个副作用都有责任主体与系统约束；
- [ ] 至少一条异常走到明确状态、接收角色和恢复条件；
- [ ] 候选上下文、工具、输出和必留记录已经列出；
- [ ] 正常样本与失败样本已经保存；
- [ ] 未验证内容被标为假设或缺口；
- [ ] 是否建设的决定包含范围、条件、负责人和下一评审时间。

## 澄川简例

| 字段 | 示例 |
|---|---|
| 任务 | 销售在会议结束后审阅 CRM 四字段更新预览，并决定是否提交沙盒 |
| AI 可做 | 提取客户原话、检索批准资料、准备建议、标记冲突 |
| AI 不做 | 批准价格、交期、商机阶段；写正式 CRM；发送外部消息 |
| 人工责任 | 销售确认业务含义；内容负责人决定资料权威性 |
| 系统责任 | 对象关联、字段白名单、鉴权、差异预览、幂等写入、状态查询和日志 |
| 失败样本 | 两份批准资料冲突时阻塞相关字段，保留其他草稿并升级内容负责人 |
| 是否建设 | 有条件继续，仅建设受控工作流，不建设开放式销售智能体 |
